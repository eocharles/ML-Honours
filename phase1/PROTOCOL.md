# Evaluation protocol (Phase 1)

Verified against the supervisors' code (`benchmark.py`, `evaluation.py`, `perturbations.py`, `models.py`, commit `6bb5a1e`).

## Data splits
```
Full dataset (569 rows)
 └─ Outer split: stratified K-fold (outer_folds = 2, seed = base_seed 20260713)
     ├─ Outer TEST  (about 285 rows)  ← untouched until a model has been selected
     └─ Outer TRAIN (about 284 rows)
          └─ Stratified split (reference_fraction = 0.20, seed = fold_seed + 1)
              ├─ Development (80%)
              │    ├─ Inner stratified K-fold (inner_folds = 2)  → validation risk
              │    └─ Perturbation subsamples (80% each)          → refits for stability
              └─ Reference (20%)
                   ├─ evaluation_rows (8)  → rows that SHAP explains
                   └─ background_rows (4)  → SHAP baseline rows
```

## Preprocessing inside the folds
Each candidate is a scikit-learn `Pipeline` (imputer, then scaler, then model). The whole pipeline is refit on the training portion every time, so imputation and scaling statistics are never learned from validation or test rows.

## No test leakage
- Candidate scores (`candidate_evaluations.csv`) use only the development and reference data.
- The selectors (`risk_only`, `stable_Xpct`, `knee`) choose using only those scores.
- The outer test set is used only afterwards, in `evaluate_selected_candidate`, to score the already-chosen candidates (`final_evaluations.csv`).
- Test results were not used to choose tolerances or selection rules.

## Seeds
| What | Seed |
|---|---|
| Base seed | 20260713 |
| Candidate pool | 4817 |
| Fold seed (outer fold k) | base_seed + k × 100000 |
| Inner risk splits | fold_seed + 4 |
| Models in inner fold j | fold_seed + 4 + 1000 + j |
| Perturbation subsamples | generated from fold_seed + 10000 |

Because every seed is fixed, rerunning gives identical scores (confirmed Nov 19 vs Nov 21).

## Search space
Candidates are generated by `generate_candidate_pool()`, which samples randomly (seed 4817) from built-in ranges. Note: these ranges are hard-coded in the function and do **not** come from the `search_space` section of the YAML config (that section is used only by the NSGA-II / grid search runner).

| Family | Setting | Values |
|---|---|---|
| Both | Scaler | standard, robust, none |
| Both | Numeric imputer | median, mean |
| Random Forest | n_estimators | 200, 400, 600 |
| Random Forest | max_depth | 4, 8, 12, 16 |
| Random Forest | min_samples_leaf | 1, 2, 4, 8 |
| Random Forest | max_features | sqrt, log2 |
| Gradient Boosting | n_estimators | 100, 200, 400 |
| Gradient Boosting | learning_rate | 0.02, 0.05, 0.1 |
| Gradient Boosting | max_depth | 2, 3, 4 |
| Gradient Boosting | min_samples_leaf | 1, 2, 4, 8 |
